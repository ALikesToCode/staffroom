Staffroom: measuring the on-device check

A developer page. With nothing added to the address it runs 24 fixed, invented cases through the on-device model's part of the check: 12 where the advice conflicts with a withheld fact and 12 where it does not. Each case runs once; add ?runs=3 to run each three times. Nothing is sent anywhere: the route is ONLY_ON_DEVICE. In these single-fact sets the model's own answer is counted: its "no" is shown as "conflict" here, though the app shows it to the teacher as a doubt and never strikes an item on the model's word alone.

?set=rules: the rule layer on its own, 62 fresh pairs of a step and a confirmed constraint. No model is used, so it runs in any browser. A case the rules get wrong stays in the set and is counted. Rules were later changed for cases outside this set by someone who had seen it, so it is no longer fresh for those rules. Its counts did not move.

?set=full: the whole sample note, a vault built from fixed entries, the constraints the rules propose (all confirmed) and six fixed drafts of five three-step items each, of which one or two in each draft have a step that a withheld fact rules out. Each row shows the two layers together, and each on its own.

?set=heldout: 16 single-fact cases the on-device model has not been tuned on, for one run.

?set=fit: 14 steps that each go against one confirmed constraint, two for each kind a rule can check. The on-device model is asked to rewrite each step so the child can follow it, as the app asks. For each the page shows whether the first answer was a rewrite, whether a rule still fires on it, and whether it repeats words of the private fact; and what the app would offer after its one retry. It does not judge whether a rewrite is good advice. Eight more pairs are steps of a lesson for the whole class with a fact about one child: there the model is asked what that child does instead. Last, 25 requests: each of the five lessons of ?set=lesson with the note about each of the sample's five children, asking what the teacher should do for that child in that lesson. For each point the page shows whether it names a stage of the lesson, whether a rule fires on it and whether it repeats private words. Its rating is left empty, for a person to fill in by reading it.

?set=lesson: five lesson plans in five subjects, written by hand as the cloud returns them, read by rule against the constraints of the sample class. Each stage that does not suit a child is labelled; the page counts what the rules caught, missed and flagged wrongly. No model is used, so it runs in any browser. As first measured: 10 of 13 caught, 3 missed, 1 flagged wrongly. Four rules were then changed after seeing these cases, so the set is no longer fresh for them: what it shows now is that the fixes hold.

?set=needs: five lesson replies written by hand as the cloud returns them, with lines for needs in them ("For Need A: ..."), read against the sample class with every need confirmed and told. Plain code, no model: the page counts the lines placed beside the right child, beside a wrong child or missing, the lines left out because their letter was not sent or they had no words, and the placed lines a rule fires on for that child. As first measured: 26 of 26 lines beside the right child, 4 of 4 left out, 5 of 5 rule hits found and none unlabelled. The replies were written by the people who wrote the code, so this shows the code does what it is meant to, not how it does on replies it has not seen. The same page runs five cases for the needs built from an exit ticket (letters J, K and L): the marks of a lesson and its topic, and the lines the next lesson would be told, with no name and no count in them. As first measured: 5 of 5.

?set=learning: twelve invented paragraphs about one child each, for the proposer of learning needs, labelled with the kinds of need in them (three have none). The rule's answer is scored against the labels. Where there is an on-device model it is asked too; it writes a free line, so the page shows each line for a person to read and counts only whether its quote is in the paragraph and its line passes the gate for a need line.

One fact at a time is the default, as in the app; add perFact=0 to ask about all of a child's facts in one prompt. For example eval.html?set=full&runs=3.
